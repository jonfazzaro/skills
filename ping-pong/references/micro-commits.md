# Micro-Commits

Micro-commits capture each discrete step of progress as a small, focused commit. In ping-pong, every handoff between agents is a commit boundary.

## Relationship to ping-pong

- Commit after each met expectation: `feat: <expectation description>`
- Commit after each design pass: `design: <what changed>`
- Never commit with unmet expectations (never commit in the red phase)
- The ping-pong cycle produces a commit history that reads as the specification of the behavior
